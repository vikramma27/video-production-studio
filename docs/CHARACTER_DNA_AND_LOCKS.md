# Character DNA, Animation Pilot and Approval Locks

## Objective
Create two original recurring 3D protagonists, one for each future channel, whose identity remains stable across episodes, thumbnails, expressions, wardrobe and camera angles. References set quality benchmarks only.

## Character development loop
1. Extract benchmark requirements: age impression, proportions, silhouette, facial expressiveness and body language.
2. Generate several original concept directions with distinct silhouettes and palettes.
3. Build Blender blockouts and turnarounds.
4. Present front, side, three-quarter and back views.
5. Build expression sheets: neutral, happy, sad, angry, surprised, fearful, embarrassed, suspicious, determined and crying.
6. Build body-action samples: idle/breathing, walk, run, stop, turn, sit, stand, point, gesture, react, talk/listen and emotional acting.
7. Test close-ups, wide shots, varied lighting and wardrobe.
8. Render short playable animation pilots with narration/dialogue and sound.
9. Collect user feedback and iterate candidate versions.
10. Freeze only after explicit approval.

## Required asset package
Character manifest; base mesh and Blender source; rig/control map; facial controls and visemes; hair/wardrobe/accessories; materials; animation actions; canonical turnarounds; expression and body-action sheets; 10–30 second playable pilots; identity regression report; approval record.

## Identity invariants
A character ID resolves to an exact approved version. Wardrobe changes do not alter face/body identity. Expressions do not alter base proportions. No silent model replacement. Every revision receives a new semantic version.

## Lock states
draft → candidate → approved → frozen → superseded. Frozen assets are immutable. Improvements branch into a new candidate; old episodes retain original dependencies.

## Pilot acceptance
Each protagonist passes canonical views, at least 10 expressions, 8 body actions, multiple camera distances and lighting setups, and five test scenes without identity drift. The user can play samples, request revisions and explicitly freeze the selected version.

Do not promise perfect procedural human modelling. Start with reviewed base meshes and agent-assisted/procedural assembly, then human art direction.
